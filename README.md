## Сборка и запуск на macOS

Открой терминал в этой папке. Например, для первого задания:

```bash
mkdir -p build

./build/task_1
```

Для остальных заданий замени `task_1` на `task_2`, `task_3` или `task_4`
в обоих местах команды сборки и в команде запуска.

xcode-select --install

После ввода примера нажми Enter. Для копилки завершение — `stop`,
для табло — `quit`; в остальных задачах количество данных известно заранее.

## 1. Дневник погоды

`new int[size]` выделяет массив температур. Его адрес хранится в
`int* temperatures`. После обработки `delete[] temperatures` освобождает
весь массив. Для массивов нужен именно `delete[]`, а не `delete`.

Три функции:

- `Average`: суммирует значения в `long long` и возвращает `double`.
- `FindMinMax`: возвращает структуру `MinMax` с двумя целыми числами.
- `CountFrostDays`: считает значения строго меньше нуля.

`const int*` означает, что функция не может изменить температуры через
этот указатель. Размер передаётся отдельно: сам указатель длину не хранит.

В `static_cast<double>(sum) / size` преобразование выполняется **до** деления.
Иначе целочисленное деление отбросило бы дробную часть.
`std::fixed << std::setprecision(1)` даёт ровно один знак после запятой.

Минимум и максимум начинаются с первого элемента, а не с нуля.
Поэтому решение работает и для всех положительных, и для всех отрицательных
температур. В условии не определён результат для `N <= 0`: программа
завершается с ненулевым кодом без вывода.

Пример:

```text
7
-2 1 3 0 -5 4 2
```

Результат:

```text
0.4
-5 4
2
```

## 2. Копилка

Все операции имеют один тип: `void Operation(long long& balance)`.
Ссылка `&` позволяет функции менять исходную сумму из `main`.
`deposit` и `withdraw` сами читают свой аргумент `k`.
Сумма хранится в `long long`, чтобы не ограничиваться диапазоном `int`.

Поле структуры `Command`:

```cpp
void (*operation)(long long&);
```

Это указатель на функцию, которая получает ссылку на `long long`
и ничего не возвращает. В таблице рядом лежат имя команды и адрес функции.
`commands[i].operation(balance)` вызывает найденную функцию.
Цепочки выбора операций по отдельным именам в `main` нет.

Собственная команда — `inc`: положить один рубль.
Она добавлена отдельной функцией и одной записью таблицы.
Число команд вычисляется по размеру таблицы; менять цикл не требуется.

Имя читается в обычный `char`-массив. `std::strcmp(a, b) == 0`
проверяет равенство текста. Сравнивать такие строки через `a == b` нельзя:
это сравнило бы адреса. `std::setw` ограничивает число считываемых символов
размером буфера с учётом завершающего нуля.

Команды вводятся по одной на строке, как требует условие.
Остаток строки отбрасывается, чтобы аргументы неизвестной команды
не стали следующей командой. `stop` завершает работу без вывода.
Проверки ошибки идут до изменения суммы. Дополнительно защищены
переполнение при пополнении и команда `inc`.

Пример:

```text
deposit 100
withdraw 200
balance
inc
balance
reset
balance
stop
```

Результат:

```text
error
100
101
0
```

## 3. Табло объявлений

Поле — `char board[5][10]`. Обращение к клетке: `board[y][x]`:
сначала строка, затем столбец. В каждой строке поля ровно 10 клеток;
завершающий нуль для самого поля не нужен.

`IsInside` проверяет координаты. `Put` использует эту проверку и возвращает
`false`, если клетка снаружи. `Text` сначала проверяет начальную клетку
и что длина слова не превышает `10 - x`. Только после успешной проверки
он вызывает `Put` для каждой буквы. При ошибке не записывается ни одной
буквы, поэтому старое объявление сохраняется полностью.

`Print` выводит клетки по одной, включая пробелы справа.
Нельзя печатать `board[y]` как C-строку: внутри строки поля нет `\0`.
`Clear` вызывается перед циклом и заполняет все клетки пробелами.
Для буфера вводимого слова предусмотрено место для завершающего нуля
и обнаружения слова длины 11, которое уже не может поместиться.
По условию слова имеют длину не больше 10.

Пример:

```text
text 0 0 Hello
put 9 4 !
text 8 0 TooLong
print
quit
```

Сначала будет `error`, затем пять строк поля. Первая — `Hello` и пять
пробелов, три средние — по десять пробелов, последняя — девять пробелов
и `!`. Неудачный `text` не меняет поле.

## 4. Импорт изображений разных размеров

Собственная задача: загрузить несколько изображений из двух форматов,
перевести их в числовую яркость и посчитать среднюю яркость каждого.
Вся обработка находится в `main`, как требуется в задании.

### Ввод

Первое число — количество изображений. Для каждого изображения:

1. Высота, ширина, тип `I` или `C`.
2. Ровно `height * width` значений по строкам.

`I`: целые яркости от 0 до 255.
`C`: символы `.`, `+`, `#`, соответствующие яркостям 0, 127, 255.
Символы можно записывать подряд или через пробелы.
Размеры и количество изображений должны быть положительными.
Неверные данные дают `error` и ненулевой код завершения.

### Почему используются эти указатели

`int*** images` хранит набор изображений разных размеров:

- `images` — указатель на массив изображений;
- `images[i]` имеет тип `int**`: указатель на массив строк;
- `images[i][y]` имеет тип `int*`: указатель на массив пикселей строки;
- `images[i][y][x]` имеет тип `int`: конкретная яркость.

Высота и ширина разных изображений могут различаться и задаются при вводе.
Размеры и сами данные поэтому хранятся отдельно; одного фиксированного
трёхмерного массива в выбранном представлении недостаточно.

В таблице `Source` сохраняются **все исходные буферы до преобразования**.
Одни буферы состоят из `int`, другие — из `char`. Общее поле `void* pixels`
позволяет хранить адрес любого из этих буферов в одной таблице.
Поле `type` сообщает, какой тип действительно находится по адресу.
После чтения всей таблицы начинается преобразование в `images`.

Через `void*` нельзя индексировать пиксели: сначала требуется приведение
к `int*` или `char*`. Приведение выбирается по метке типа, а не угадывается.
При освобождении памяти выполняется такое же приведение и соответствующий
`delete[]`. Доступ к неверному типу и `delete[]` напрямую для `void*`
недопустимы.

Это объяснение обосновывает выбранную архитектуру: динамический набор
двумерных изображений и общую таблицу разнородных исходных буферов.
Существуют другие архитектуры без этих типов, но здесь оба типа участвуют
в хранении и обработке данных, а не служат печати адресов.

Пример:

```text
2
2 3 I
0 10 20
30 40 50
1 4 C
.+##
```

Результат: номер изображения с единицы и средняя яркость.

```text
1 25.0
2 159.2
```

Память освобождается в обратном порядке: строки каждого изображения,
массив строк, общий массив изображений. Сырые буферы и таблица источников
также освобождаются. При неверном вводе уже выделенные буферы очищаются.
Как и в учебных задачах с `new`, предполагается, что запрошенный объём
памяти доступен; отдельная обработка `std::bad_alloc` не добавлена.

## Отправка в Git

Создай пустой репозиторий на выбранном Git-хостинге. Затем из этой папки:

```bash
git init
git add .
git commit -m "Add homework 1 solutions"
git branch -M main
git remote add origin URL_ТВОЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Замени `URL_ТВОЕГО_РЕПОЗИТОРИЯ` на адрес нового репозитория.
В архиве есть `.gitignore` и `.clang-format`: при распаковке и копировании
убедись, что они остались в корне. `git add .` добавляет `.clang-format`,
но не добавляет файлы, перечисленные в `.gitignore`.
Ни бинарные файлы, ни папку `build` загружать не нужно.
Перед сдачей разбери код и убедись, что можешь объяснить каждый указатель,
проверку и освобождение памяти. Особенно внимательно — собственную задачу 4:
её обоснование преподаватель оценивает вручную.

## Выполненные проверки

Все программы собраны с `-std=c++17 -Wall -Wextra -Werror -pedantic`.
Форматирование проверено по приложенному `.clang-format`.
Пройдено 242 проверки: примеры, граничные случаи, случайные данные
со сравнением с независимым расчётом и запуски с AddressSanitizer / UBSan.
Проверялись также сохранение поля при неудачной записи, пробелы при печати,
переполнение суммы копилки и освобождение буферов при ошибках ввода.
Автоматический поиск утечек LeakSanitizer в окружении проверки недоступен;
соответствие выделений и освобождений памяти проверено по коду.
